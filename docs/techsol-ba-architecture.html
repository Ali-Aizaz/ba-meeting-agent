How one meeting runs

The adapter joins, posts consent, and turns captions on. Caption lines accumulate with speaker and meeting time.

“Hey BA” starts the addressed loop. Anything else stays quiet, except a complete overheard task, which is written and confirmed.

Save runs when asked and when the meeting ends. The bot leaves one minute after it is the last one in the call.

Select any box for what that part does.

Meet adapter

Chromium runs headed under Xvfb on the cloud server, one meeting at a time. It joins Google Meet as TechSol BA (a saved sign-in, or a guest the host admits), with the mic and camera off. The first chat line is the consent notice. It turns captions on, leaves one minute after it is alone, and saves before it goes. Chat posts are allowed only for consent, a reply, a task confirmation, or the saved-notes link.

Google Meet

The only platform this build joins. Live captions are Meet’s own speech-to-text, drawn in the page for the participant who turns them on. There is no separate caption API. Chat is plain text. Zoom and Teams stay on the diagram as a second adapter.

Caption line

A script watches the captions region and commits a line when the text settles, the speaker changes, or a new row replaces it. Speaker aliases are applied, then the line is stored. The clock is time since the bot was admitted. Captions are strongest in English, and the page structure can change. If they never appear, typed “Hey BA” still works. No second speech-to-text service is added.

Chat message

Read from the same page. The bot’s own messages are ignored. A typed “Hey BA” is a trigger even when captions are empty, and it is how someone asks the bot to save or to leave.

Wake phrase

Accepts “hey ba”, “hey bea”, “hi ba”, “okay ba”, and “ok ba”. Rejects lookalikes such as “hey bob”, “bay area”, and “the BA team”. The question is the words after the phrase. If the phrase arrives alone, it waits a few seconds for the same speaker, then asks one short clarifying question. A follow-up to that question does not need a second “Hey BA”. Ordinary talk produces no trigger.

Agent loop

Runs only after a wake phrase. The prompt is the persona, a short digest of this meeting, and the question. For a car question it calls search_knowledge first, then search_cars if the local hit is weak or the fact is current or specific. It calls create_task only when it has a task, an owner, and a due date; otherwise it asks one question. It calls save_meeting when asked to save. The model does not post to Meet itself.

Knowledge base

Short Markdown files we write under data/knowledge/, such as hybrid, EV, and a few sourced examples. search_knowledge scores chunks by keyword overlap and returns the file and heading. There is no vector database and no hard-coded question-to-answer table. A strong local hit does not go on to web search.

Guardrails

A car fact in chat must cite a knowledge-base file or a URL, or the reply says it is not sure. An uncited number is regenerated once, then replaced with a not-sure line. search_cars is refused if the query contains a caption line, the participant list, or a Notion URL. Consent and task confirmations skip this check.

Chat reply

One reply per trigger, after the guardrails pass. Meet chat does not render Markdown, so the answer is a few sentences or a small plain-text table. A save posts the Notion URL with reason MEETING_SAVED when people are still in the call.

Task extractor

Runs on recent caption lines and does not wait on a reply. The model returns JSON: task, owner, due date, and who said it. Web search is off. A question to the bot is not a task. An overheard task missing an owner or a due date is dropped, and the bot does not interrupt the meeting to ask. A complete task calls create_task directly.

Confirmation

A new row is confirmed in chat, for example “Task added: Ali — cost sheet — Fri”. If that task and owner already exist, including from an earlier meeting, the chat says it is already tracked and nothing is written again. A failed write is also said in chat.

Meeting memory

Stores caption lines, tasks, and earlier replies so a restart can continue. digest() adds participants, open tasks, and the last few minutes to the next “Hey BA” prompt, and it is capped so a long meeting still fits. Older lines stay in SQLite and go into the summary at the end. This store is not an index of past meetings.

save_meeting

Triggered by “Hey BA, save the meeting”, and by the adapter when the meeting ends or someone tells the bot it can go. The summary is a short paragraph from the model, with web search off, plus the task list. The transcript sits in a collapsed toggle. Running save twice updates the same page. The empty page is created at join so the consent message can include a real link.

OpenAI

The provided key. Default client is the OpenAI Responses API; Claude or Gemini can sit behind the same interface if the key is not OpenAI. Web search is enabled only inside search_cars. Task extraction and the meeting summary call the model with web search off. The model id is configuration, not hard-coded.

Public web

OpenAI fetches public pages. The query is the car question, such as a current price or a named model. The transcript, the participant list, and Notion contents are not placed in that query. The chat reply shows the URL. If the notes and the search are both empty, the bot says it is not sure and does not invent a spec.

Notion

Two places: a summary page, and tasks with owner and due date. Property names come from notion_schema.yaml, so the attached database can be mapped without code changes. Dedup is normalised task text plus owner, including earlier meetings. Decisions, Requirements, and Risks are not separate databases in this build.

Second platform

The same MeetingPlatform interface, with another adapter. Meet captions do not transfer, so that platform would need its own transcript source. This build joins Google Meet only.

Voice reply

The chat reply would stay. A short spoken version would use a text-to-speech API on the provided key, such as OpenAI speech. The mic would turn on only while the bot speaks. Today the mic stays off and every answer is typed.

Decisions, Requirements, Risks

Three more databases linked to the meeting summary. In this build those topics are mentioned inside the summary when they came up. They are not their own rows.

BOM and compare

build_bom would return part, quantity, cost, and supplier. compare would return a short trade-off. Both would read the same knowledge base and would still not send the transcript out. Neither tool exists in this build.

Past meetings

When someone asks about a previous meeting, read older summaries and open tasks from Notion. Today the memory used in a reply is this meeting only. Dedup against tasks already stored from earlier meetings still happens at write time.

Data-flow rule

The knowledge base is ours. The internet is used to fetch public car pages in. search_cars is rejected when the query contains a caption line, a participant list, or a Notion URL. The digest may still be sent to the LLM for a reply. It is not copied into the search query.
