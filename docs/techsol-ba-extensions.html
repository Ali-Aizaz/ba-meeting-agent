Chrome Extension (MV3) — extension/

Unpacked Manifest V3 extension (background.js, content.js, popup.html, popup.js). Watches for Google Meet URLs (https://meet.google.com/xxx-xxxx-xxx), triggers POST /join on the Cloudflare Worker automatically when a Meet tab opens or joins, auto-clicks the Google Meet Admit button when “TechSol BA” knocks in the lobby, detects local “Hey BA” wake phrases for instant visual feedback, and renders a live status toast in the bottom-right corner of Google Meet.

Cloudflare Worker Edge Router — cloudflare/src/index.ts

Routes POST /join (authenticated with constant-time crypto.subtle.timingSafeEqual against BA_WEBHOOK_SECRET), GET /status?peek=1 (checks container state without waking a sleeping container), and GET /status to the singleton BaContainer Durable Object. Non-status paths (such as /favicon.ico or scanner probes) return 404 at the edge so they never wake the 4 GiB container.

Cloudflare Container (standard-1) & Multi-Meet Keep-Alive

Runs the Playwright + Xvfb Docker image on a standard-1 instance (4 GiB RAM, 0.5 vCPU, sleepAfter = "3h"). With BA_BROWSER__KEEP_ALIVE=true, Chromium stays open and signed in between meetings: a new POST /join switches the running session to the new Meet URL without cold-starting the browser.

Live Activity Toast HUD — status.py & content.js

Every stage of the agent (hearing “Hey BA”, searching data/knowledge/, running search_cars, extracting overheard tasks, saving to Notion) emits structured activity events with sequence numbers via StatusState.record_activity(). These appear both on the bot’s own Playwright overlay (adapter.show_toast) and in the user’s Chrome Meet tab via content.js.

Google Meet Adapter (Built · Must #1)

Driven by Playwright in headed Chromium under Xvfb. Joins with camera and microphone muted, rewrites WebRTC SDP offers/answers so incoming video tracks are a=inactive (saving CPU on 0.5-vCPU containers), posts the consent notice with the pre-created Notion summary URL, turns on live captions, and serializes chat DOM actions via _ui_lock.

Google Meet Call (Built · Must #1)

The live meeting platform built today. Uses Google Meet’s built-in closed captions for speech-to-text (as required by the 25 Oct revision) and the in-call chat panel for both “Hey BA” triggers and bot replies.

Captions & Chat Stream (Built · Must #2)

CaptionPump and Stabilizer poll the Meet caption DOM every 300ms, wait for in-place caption edits to settle, normalize speaker names via config/speaker_aliases.yaml, attach meeting-relative timestamps ([mm:ss]), and persist every committed line to SQLite WAL (captions table).

Extension: Second Meeting Platform (Zoom / MS Teams)

Diagram-only extension: src/ba_agent/bot/base.py defines the MeetingPlatform protocol (join, enable_captions, drain_caption_frames, collect_chat, post_chat, leave). Extending to Zoom Web Client or Microsoft Teams adds ZoomAdapter / TeamsAdapter implementing the exact same interface while keeping AgentLoop, TriggerDetector, MeetingStore, and NotionService unchanged.

“Hey BA” Wake Phrase Detector (Built · Must #3)

Matches spoken or typed “Hey BA” (plus caption phonetic variants like “Hey Bea”, “Hi BA”, “OK BA”, and chat @ba) while rejecting lookalikes (“Hey Bob”, “Bay Area”, “the BA team”). Supports bare “Hey BA” with a 5-second pause wait and a 20-second same-speaker follow-up window.

Local Car Knowledge Base (Built · Must #4)

Curated Markdown files in data/knowledge/ (hybrid.md, ev.md, body-and-chassis.md, safety.md, examples.md). Indexed by KnowledgeIndex using heading-aware chunking and keyword-overlap scoring. Checked first on every car question; strong local hits answer directly with (src: filename.md) without calling web search.

Data-Flow Guardrail Gate (Built + Extension #5 Rule)

Enforces the assignment’s strict data-flow boundary: “own knowledge base; internet only to fetch data in, meeting data never sent out.” Before search_cars(query) calls OpenAI web_search, query_allowed() and strip_meeting_text() verify that no non-addressed transcript snippets (≥12 chars), participant names (excluding car brand names), or Notion/Meet URLs are present in the outbound search string.

Meeting Chat Reply & Citation Gate (Built · Must #3 & #4)

Every car reply passes through guardrails/citations.py to verify it cites a local file (src: ...) or a web URL. Uncited numbers trigger a single regeneration prompt and otherwise fall back to “I’m not sure from the car notes or web search.” OutputGate guarantees at most one chat reply per trigger.

Extension: Car Parts / BOM Tables & Option Comparisons

Diagram-only extension: Adds two structured tools to AgentLoop: build_bom(system) (returns part, quantity, unit cost, extended total, lead time, and supplier from local parts tables, flagging lead times ≥12 weeks and single-source suppliers) and compare(option_a, option_b, criteria) (returns a side-by-side trade-off table capped at ≤8 rows, ≤5 columns, ≤120 chars/line for Meet chat).

Extension: Voice Replies via Text-to-Speech API

Diagram-only extension: Keeps the full cited text reply in Meet chat while synthesizing a concise 1–2 sentence spoken summary via an allowed TTS API (e.g., OpenAI audio.speech). Output is routed into Chromium’s virtual microphone via a PulseAudio null-sink, unmuting the Meet mic only for the duration of playback and re-muting immediately afterward.

OpenAI Web Search (Inbound Public Car Facts Only)

Used only inside search_cars(query) when the local knowledge base score is below min_score or the question asks for live/current model pricing or specs. Disabled (enable_web_search=False) during task extraction and meeting summarization.

Notion Tasks Database (Built · Must #5)

Stores tasks with Task, Owner, and Due date, created either explicitly via “Hey BA, add a task…” or automatically from overheard speech via _Extractor (using a local task-signal pre-filter + LLM JSON extraction + deterministic regex fallback). Deduplicates across all meetings via normalized dedup_key(task, owner) and an in-memory cache.

Notion Summary Page & Live Sync (Built · Must #5)

Pre-creates the Notion summary page at meeting join (ensure_summary_page) so the consent message includes a live link. Syncs live notes in the background during the call (live_notes()) and writes the LLM executive summary, task list, and collapsed full transcript toggle block on “Hey BA, save the meeting” and at call end.

Extension: More Notion Databases (Decisions, Requirements, Risks)

Diagram-only extension: Extends the background transcript classifier and NotionService with three additional databases mapped in config/notion_schema.yaml: Decisions (Decision, Rationale, Decided By, Status), Requirements (Req ID, Requirement, Priority, Category), and Risks (Risk, Severity, Likelihood, Mitigation, Owner), each linked to the Meeting Summary page via a Notion Relation property.

Extension + Built Recall: Memory Across Past Meetings

Spec Extension + Built Recall: NotionService.database_context() queries historical summaries and open tasks from Notion, and MeetingStore.stored_context() queries earlier meetings in SQLite. AgentLoop._full_digest() merges both into <meeting_digest> so questions like “Hey BA, what did we decide in the last meeting?” or “What tasks are still open?” are answered accurately.
